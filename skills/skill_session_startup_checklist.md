**Established:** 2026-04-14  
**Status:** MANDATORY — Execute at session start every time  
**Purpose:** Load state, confirm discipline, prevent regression from Session 002 failures

---

## When to Use This
**At the start of EVERY session, BEFORE accepting any task.**

Do not skip. Do not shorten. Run all 7 steps (~10 minutes).

---

## The 7-Step Startup Checklist

### Step 1: Memory Load (2 minutes)
```
- [ ] Read MEMORY.md index (top section)
- [ ] Search MEMORY.md for task-related keywords (if user has given task preview)
- [ ] Read any relevant memory files discovered
- [ ] Note locked-in decisions, corrections, or learnings from prior sessions
- Question: "Do I understand the current state?"
```

**If unclear:** Ask user for context before proceeding.

---

### Step 2: Protocol Confirmation (1 minute)
```
- [ ] Read CLAUDE.md — project instructions
- [ ] Confirm current focus from "Current Focus" section
- [ ] Check "Open Issues" list
- [ ] Review relevant SOP from skills/ directory
- Question: "Do I know what I'm building?"
```

**If unclear:** Ask user to clarify scope.

---

### Step 3: Execution Discipline Check (1 minute)
```
- [ ] Execution Discipline Protocol is loaded and active
- [ ] Confirm: I will NOT guess, embellish, or fabricate
- [ ] Confirm: I will check for existing patterns/templates FIRST
- [ ] Confirm: I will use verified sources only
- [ ] Confirm: I will run 8-item self-QA before sending anything
- Question: "Is discipline my priority, not speed?"
```

**If unsure about any rule:** Review execution_discipline_protocol.md again.

---

### Step 4: Task Type Identification (2 minutes)
**For every task user gives, ask:**

```
- Does this match an existing workflow? (CLAUDE.md, SESSIONS.md)
- Does this match an existing SOP? (skills/ directory)
- Does this match a previously approved template? (scripts/, prior emails)
- Does this match previously approved output? (MEMORY.md references)
```

**Result:**
- **YES to any of above:** This is RECURRING WORK → apply full Execution Discipline Protocol
- **NO to all:** This is GENUINELY NEW work (rare) → still apply protocol, but expect more clarification

---

### Step 5: Verify Source Material (2-3 minutes)
```
- [ ] User has provided all required data (or I know where to get it)
- [ ] I have access to relevant databases (Markaz, Teams, Gmail, etc.)
- [ ] I have located reference template/SOP if applicable
- [ ] I understand format/tone/structure expected
```

**If missing:** Ask user for clarification BEFORE starting work.

---

### Step 6: Search for Prior Work (3-5 minutes)
**Before creating anything new, search:**

```
1. MEMORY.md for similar completed work
2. SESSIONS.md for prior task logs
3. scripts/ for reference implementations
4. CLAUDE.md → Quick Reference for templates
5. skills/ for relevant SOPs
6. Ask: "If this file/email/report exists, where would it be?"
```

**Only after thorough search:** Conclude it doesn't exist and proceed to create.

---

### Step 7: Lock-in Confirmation (1 minute)
**For recurring work, VERIFY locked-in standards:**

```
- [ ] Rejection emails: Format confirmed (no asterisks? v8 design?)
- [ ] Attendance reports: 10-section structure confirmed
- [ ] Values emails: Tone confirmed (warm? transcript evidence?)
- [ ] All candidate-facing emails: Jargon-free? No internal names?
- [ ] Any other format corrections from prior sessions locked in?
```

**Check:** MEMORY.md for any "Feedback" type memories about format/tone.

---

## Checkpoint: Ready to Proceed?

**Can you answer YES to ALL of these:**
```
- [ ] I have read MEMORY.md and understand current state
- [ ] I understand the task and its scope
- [ ] I know where the reference/template is (or confirmed it doesn't exist)
- [ ] I understand the locked-in format/tone/structure
- [ ] I have verified source material is available
- [ ] Execution Discipline Protocol is active in my thinking
- [ ] I am NOT going to guess, assume, or fabricate
```

**If any NO:** Stop. Ask user for clarification. Do not proceed until all are YES.

## The 8-Item Self-QA Checklist
(Run BEFORE sending ANY output — from Execution Discipline Protocol)

- [ ] **File names and existence** — Verified actual file names, checked they exist or need creating
- [ ] **Formatting** — Matches approved format exactly (logo, headers, fonts, spacing, color codes, section structure)
- [ ] **Tone** — Matches approved tone (warm vs. direct, jargon-free, "we" voice, etc.)
- [ ] **Duplication** — No repeated sections, greetings, headings, or content
- [ ] **Jargon removal** — No internal terminology ("GWC", "Zero In Call", process names, reviewer names)
- [ ] **Encoding/spelling artifacts** — No em dashes showing as garbage, no weird characters, no typos
- [ ] **Consistency with approved examples** — Compared to reference work, structure/tone/format matches
- [ ] **Factual grounding** — Every claim tied to source material (user data, Markaz DB, approved template, prior decision)

**Only send work after ALL 8 checks pass.**
