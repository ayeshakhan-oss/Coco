## The 8 Items

**Before submitting ANY work, verify:**

1. **✓ File names and existence** 
   - Verified actual file names used are correct
   - Checked that files exist (or confirmed they need to be created)
   - No typos in file paths or names

2. **✓ Formatting**
   - Matches approved format exactly (logo, headers, fonts, spacing, color codes, section structure)
   - If locked format exists, compared side-by-side and confirmed match
   - No deviations from locked standard

3. **✓ Tone**
   - Matches approved tone (warm vs. direct, jargon-free, "we" voice, etc.)
   - If prior example exists, compared side-by-side and confirmed match
   - No tone regression from prior approved work

4. **✓ Duplication**
   - No repeated sections, greetings, headings, or content
   - Each section appears exactly once
   - No redundant paragraphs or runaway text

5. **✓ Jargon removal**
   - No internal terminology ("GWC", "Zero In Call", process names, internal acronyms)
   - No reviewer/interviewer/manager names exposed to candidates
   - No Taleemabad-internal framework terminology in external-facing content
   - Candidate-facing work is clean of all jargon

6. **✓ Encoding/spelling artifacts**
   - No em dashes showing as garbage characters
   - No weird Unicode or encoding artifacts
   - No typos, misspellings, or grammatical errors
   - Spell-checked and reviewed for readability

7. **✓ Consistency with approved examples**
   - Compared to reference work / prior approved example (side-by-side)
   - Structure matches (same section order, same hierarchy)
   - Tone matches (same voice, same formality level)
   - Format matches (same colors, same fonts, same spacing)

8. **✓ Factual grounding**
   - Every claim is tied to source material (user data, Markaz DB query, approved template, prior decision)
   - No inferences, assumptions, or plausible-language fill-ins
   - If data thin, output is thin too (not embellished to improve completeness)
   - All numbers, dates, names, facts verified against source

## How to Use This Checklist

### Before Submitting Work:
1. Open this checklist
2. Go through all 8 items one by one
3. For each item, answer: "YES, I verified this" or "NO, needs fixing"
4. If ANY item is "NO" → fix it before submitting
5. Only submit when ALL 8 are "YES"

### Output Format (Show Your Work):
When submitting work to Ayesha, include checklist results:

```
SELF-QA RESULTS:
✓ 1. File names verified — [details]
✓ 2. Formatting matches approved template exactly — [details]
✓ 3. Tone consistent with [prior example] — [details]
✓ 4. No duplication — checked all sections once
✓ 5. No jargon — removed "GWC", internal names, internal terminology
✓ 6. No encoding artifacts — spell-checked, grammar verified
✓ 7. Consistent with [reference work] — side-by-side comparison done
✓ 8. All facts grounded in [source] — no assumptions

READY FOR REVIEW
```

---

## Failsafe: If You Fail Any Item

**Do not submit.** Instead:
1. Fix the item that failed
2. Re-run the checklist
3. Try again until all 8 pass
4. Only then submit

---

## Why This Matters

- **Item 1-2:** Prevents technical errors (wrong files, formatting drift)
- **Item 3-4:** Prevents tone/style inconsistencies (user has to re-read and correct)
- **Item 5-6:** Prevents candidate confusion (jargon, typos break trust)
- **Item 7:** Prevents regression (forgetting locked-in formats from prior sessions)
- **Item 8:** Prevents cascading errors downstream (decisions based on false data)

**Goal:** Reliable first-pass quality. Work that needs zero revisions. Work that's ready to send immediately after review.
