# One Master File Per Skill (2026-06-09)

## Rule
**For every skill (candidate communication, talent sourcing, hiring operations, etc.), maintain ONE master file that consolidates all rules, philosophy, guidance, and standards.**

Never scatter related rules across multiple files.

## Why
- Prevents confusion about which file is current
- Stops rule drift (one source of truth)
- Makes updates faster (edit one place, not five)
- New skills auto-inherit the pattern
- Reduces back-and-forth ("oh, update the tone file too?")
- Both Ayesha and Coco know exactly where to look

## How to Apply
When tasked with updating a skill:
1. **Check:** Does this skill already have a master file? If yes, update it.
2. **If no:** Create ONE file (e.g., `CANDIDATE_COMMUNICATION_TONE_PHILOSOPHY_LOCKED.md`)
3. **Consolidate:** Pull all scattered rules into this one file
4. **Delete/archive:** Old scattered files (don't keep them around)
5. **Link:** All related skill files link to this master, not duplicate rules
6. **Update MEMORY.md:** Index points to the ONE master file

## Examples
✅ **Correct:**
- `CANDIDATE_COMMUNICATION_TONE_PHILOSOPHY_LOCKED.md` ← All candidate feedback rules in ONE place
- All 4 skills (CV rejection, GWC rejection, values feedback, warm bench) link to it

❌ **Incorrect:**
- `rule_all_feedback_emails_use_locked_tone.md` + `lesson_no_intent_inference_rejection_emails.md` + `warm_bench_final_locked_approach.md` ← Scattered, duplicated, confusing

## Locked Pattern (2026-06-09)
From session: Consolidation is the default for all skill work going forward.
- Candidate Communication Skill → ONE master file
- Talent Sourcing Skill → ONE master file
- Hiring Operations Skill → ONE master file
- Any future skill → ONE master file

**This is automatic. Do not ask Ayesha to remind you.**
