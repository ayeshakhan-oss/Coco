## CONTENT STRUCTURE (4 Sections + P.S.)

1. **Opening Paragraph**
   - Lead with decision/opening phrasing
   - Show company vulnerability ("we were worried", "the room felt")
   - Specific interview moment with timestamp
   - Analysis: Why this moment matters to us

2. **"What Genuinely Impressed Us" Section**
   - 1-2 ADDITIONAL interview moments (different from opening)
   - Each with SPECIFIC timestamp
   - Deep analysis: "Why does this rare? What does it reveal about their character?"
   - Not just "what they did" but "why it matters"

3. **"Here's the Part We Need to Be Honest About" Section**
   - Name the gap directly
   - Frame as ROLE-SPECIFIC, not personal failing
   - Show we understand their potential
   - NOT: "You lack X" 
   - YES: "In our technical interview, we found... For this role, at this moment, that gap matters because..."

4. **"Here's Where We Want to Leave Things" Section**
   - **CRITICAL:** Do NOT suggest what they should do
   - ❌ "You should study X"
   - ❌ "We recommend taking courses in Y"
   - ✅ "We'd genuinely like to stay connected. If opportunity aligns with your experience and strengths, we'd welcome talking again."

5. **P.S. (BEFORE signature)**
   - The ONE thing the room will remember
   - Tied to subject line's story
   - Positive reinforcement
   - Make it screenshot-worthy
   - Example: "P.S.; That MATLAB-to-Python pivot still stands out. That kind of initiative is genuinely rare."

## LANGUAGE RULES (CRITICAL)

✅ **DO:**
- "This isn't a yes for now"
- "Technical interview" (NOT "GWC" - internal jargon)
- Hyphens ONLY in compound words (co-founder, etc.)
- Specific timestamps: "At 18 minutes...", "About 35 minutes in..."
- Company context: "the room felt", "we were worried", "the panel shifted"
- "We" voice exclusively (never "I")
- Specific moments quoted from candidate
- Deep WHY analysis

❌ **DON'T:**
- Em dashes (— becomes - or remove)
- Prescriptive advice in final section
- "I" voice
- Generic timestamps ("In the interview")
- "GWC", "KCD", "TBC" terminology
- Interviewer names
- Vague references ("Your insight was great")

## PROCESS DISCIPLINE CHANGES

### 1. SEND LOG (NEW MANDATORY)
Record every send:
- Date & time
- Recipient email
- Subject line
- First 300 characters of body
- Full body content
- Status: sent

When error reported → reference SEND LOG to self-diagnose, don't ask user to explain

### 2. TESTED VERSION VERBATIM (NEW MANDATORY)
- Never recreate approved content
- Live send = exact copy of pilot version
- No variations, no "improvements"
- If change needed → test it first

### 3. SIDE-BY-SIDE VERIFICATION (NEW MANDATORY)
Before ANY send:
- Show approved version
- Show actual version
- Line-by-line comparison
- Get explicit user sign-off

### 4. SELF-DIAGNOSIS (NEW MANDATORY)
When user reports error:
- Reference SEND LOG
- Read exact content sent
- Identify discrepancy myself
- Tell user "I sent X instead of Y because [reason]"
- Don't ask user to explain

### 5. LOCKED TEMPLATE ENFORCEMENT (NEW MANDATORY)
- Approved content lives in ONE place
- Sending scripts ONLY pull from approved place
- Any modification requires re-approval
- Use same script for pilot and live (just pilot_mode flag)
