Nothing was fabricated, but **nothing inside quotation marks may be approximate.** 🔴 **Never "tidy" text inside quote marks, and never echo a candidate's typo back at them** (unquote and paraphrase instead). 🔴 SMG submissions arrive as **Markaz Drive links, not email attachments** (Rule 18 assumes attachments): open the folder IDs recorded in the evaluation scripts using **`token_sheets_broad.json`**, extract with `scripts/evals/fetch_submission_corpora.py` (docx text boxes + tables, pptx notes, xlsx values **and** formulas, PyMuPDF for PDF), then audit the **letter's** own quotes and numbers, not the evaluation record's. Harness: `_quotes_are_verbatim()` HARD BLOCKS any quoted phrase absent from that candidate's corpus. See [memory/case_study_outcome_email_type_2026_09_08.md](memory/case_study_outcome_email_type_2026_09_08.md).

27. **🔒 SCORING: USE THE WHOLE SCALE, AND CHECK THE PER-QUESTION MINIMUM BEFORE REPORTING (2026-09-02)** — I scored 25 RM case studies and put **all 25 above the published 70% bar** (mean 88.3, lowest exactly 70.0). Ayesha challenged it — *"were they actually that good?"* — and she was right. **The tell is `min(mark) per question`:** on four of nine questions the *worst* answer of 25 still scored 70%, and I never once used the bottom half of the scale. Three causes, in order of size: **(a) anchors of 5/3/1 create a ~20% floor** — a submission answering the wrong question still banked 20% of every item, so nine questions of floor is ~20 free points; **(b) crediting structure and plausible prose over correctness** — I let a well-organised answer built on a misreading score well; **(c) six of nine questions do not discriminate for an internal pool** (pushback, burnout, people leadership are table stakes for people already doing the job). 🔴 **Fixes, all mechanical: convert on the full 0-5 scale with a real zero (5→100%, 4→80%, 3→60%, 2→40%, 1→20%, 0→0); write the benchmark's caps as rules BEFORE scoring and apply them without discretion; tick every required element individually; and run the contradiction test before reporting** — I had written that only 6 of 25 read the data correctly while scoring that same question at 85%, and did not notice. Strict re-mark moved the mean 88.3 → 75.0, the spread 30 → 44 points, and put 8 of 25 below the line. 🔴 **When a cap turns out to be wrong, split it and re-check every candidate already scored under it** (C1 became C1a/C1b at candidate 2; the earlier one was re-checked and held). 🔴 **The score writer must be atomic + utf-8 + `ensure_ascii=True`** — a cp1252 `UnicodeEncodeError` truncated `scores.json` to 0 bytes and lost 7 records; write to `mkstemp` in the same dir then `os.replace`. 🔴 **A high mean from a single unmoderated marker is exactly the pattern leniency produces — say so, and name the cheap check** (have a second reader re-score the candidates clustered just above the line). See [memory/lesson_scoring_anchor_floor_inflation_2026_09_02.md](memory/lesson_scoring_anchor_floor_inflation_2026_09_02.md) · [memory/project_rm_internal_case_study_round_2026_09_02.md](memory/project_rm_internal_case_study_round_2026_09_02.md).

27. **🔒 SKILL FILES: NUMBER THEM, AND VALIDATE THE FRONTMATTER YAML (2026-09-08)** — Claude Code discovers a skill **only** at `.claude/skills/<name>/SKILL.md`. Files inside a skill folder are supporting docs, **never separately discoverable**, and a nested `SKILL.md` inside another skill's directory is not picked up: **there is no sub-skill concept.** The folder listing is therefore the only navigation, so **the filename and its sort position are the whole UX**. Skill 01's eight type files are numbered **01-08 by type**, matching the registry inside SKILL.md — keep that, and **never name a new type file so it can be mistaken for its neighbour** (`case-study-outcome` vs `case-study-update` were one word apart and truncated identically; Ayesha could not tell them apart and asked three times). 🔴 **A bare `word: ` inside an unquoted YAML description is a mapping delimiter and silently kills the frontmatter** — the skill then loses its whole description and stops triggering reliably. **Always `yaml.safe_load` the frontmatter after editing it** (cap: 1,536 chars for description + when_to_use). 🔴 **A skill description must advertise EVERY type it covers** — Skill 01's stopped at type #5, so #6/#7/#8 were unreachable by triggering for weeks. 🔴 **Renaming skill files:** confirm no hook matches the filenames (memory hooks key off `memory/*.md`, not skill files) → `git mv` → rewrite references repo-wide → **verify every markdown link resolves on disk**. ⚠️ **`.claude/skills/` is NOT deployed to Railway** — the Dockerfile copies only `webapp/`, `alembic/`, `assets/`, four `scripts/` modules and the tone master. Skills are read by Claude Code from the repo; a *type* ships to Railway via `EMAIL_TYPES` + prompts + the frontend picker (Rule 25). ⚠️ **`07_contract-drafting/SKILL.md` still has no frontmatter.** See [memory/case_study_outcome_email_type_2026_09_08.md](memory/case_study_outcome_email_type_2026_09_08.md).

25. **🔒 A SUPERSEDED RESULT MUST BE RETIRED EVERYWHERE, AND A REPORT THAT LIVES ONLY IN AN EMAIL DOES NOT EXIST (2026-09-08)** — On the RM round a strict re-mark replaced a first pass (mean 88.3, nobody below the 70% bar → mean 75.0, **8 below**). The new numbers went into the report and nowhere else, so the old ones stayed live in the tracker's **Scores tab**, in the evaluation **Google Doc**, and in a **DRAFT-for-QA benchmark PDF**. Ayesha had to correct the same link **three times**. Three rules follow. **(a) Retire the old numbers the same day, in every artefact** — sheet tabs, Docs, PDFs, index links — or relabel them SUPERSEDED in place. **(b) Fix the artefact, never just re-point the link.** Re-pointing an index only changes which wrong thing is one click away. A Doc is corrected **in place** via `drive.files().update(fileId, media_body=html, body={"mimeType": "application/vnd.google-apps.document"})`, which keeps the ID so every already-shared URL resolves to the truth; a new file leaves the wrong numbers live at a link people hold. **(c) A title is not evidence of content, and an emailed report is invisible.** The report she actually wanted existed only as the **body of an email** (its sole attachment was a different document), so no Drive search could ever surface it. **Publish an inline report to Drive the same day it is sent**, and when someone says a link is wrong, **ask which artefact they mean before swapping it a second time**. Verify by reading content back and asserting a figure only the superseded version contains is now **ABSENT**, not merely that the new one is present. See [memory/rm_marked_scripts_sheet_2026_09_08.md](memory/rm_marked_scripts_sheet_2026_09_08.md).

## 🧠 Memory System (Three Tiers + Automated Hooks)

| Tier | File | Purpose | Updated by |
|------|------|---------|------------|
| **Active** | [memory/session_active.md](memory/session_active.md) | Current session notes: task, decisions, mistakes, files touched | Coco during work |
| **Curated** | [memory/MEMORY.md](memory/MEMORY.md) + *.md | Project knowledge: skills, locked templates, decisions, learnings | Coco after sessions |
| **History** | [memory/lessons_learned.md](memory/lessons_learned.md) | Structured mistake→rule log: what went wrong, how it was fixed, the rule | Stop hook (automatic) |

**How it works:**
1. **UserPromptSubmit hook** (automatic at session start) — Detects keywords in your prompt (e.g., "warm bench", "cv screening") and injects the 3-5 most relevant memory files into context. No manual lookup needed.
2. **Stop hook** (automatic at session end) — Reads session_active.md, extracts Mistakes/Corrections section, appends structured entries to lessons_learned.md, resets session_active.md for next session.

**Result:** Every session starts rich with relevant context. Every mistake gets logged as a rule for the future.

## 🛡️ Three-Layer Pre-Draft Enforcement (2026-06-08)

**Status:** ✅ PRODUCTION READY — All 4 email types protected from draft to send

**PROBLEM SOLVED:** Initial harness validated only at SEND time. Bad drafts were already written. Ayesha had to catch mistakes.

**SOLUTION:** Three-layer architecture prevents bad drafts at SOURCE.

---

### Layer 1: Template Injection (Draft Time Prevention) ✅ ACTIVE
When you type "draft gwc rejection", the UserPromptSubmit hook automatically injects:
- **Locked template HTML** (you EDIT it, can't create custom HTML from scratch)
- **Pre-flight checklist** (mandatory acknowledgment before drafting)
- **Locked approach/SOP** (rules right in context)
- **Three-layer enforcement guide** (architecture reference)

**Benefit:** Can't start wrong because template is right there. Structure prevents deviation by design.

---

### Layer 2: Pre-Flight Checklist (Pre-Draft Gating) ✅ ACTIVE
MANDATORY checklist before you can draft:
- [ ] I have read the locked template
- [ ] I have read the locked approach
- [ ] I understand the 7 HARD BLOCKs
- [ ] I am ready to EDIT (not CREATE) the template

**Benefit:** Blocks drafting until all locked files are acknowledged. No skipping.
