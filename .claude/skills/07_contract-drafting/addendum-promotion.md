# Sub-skill: Addendum (Same-Team Promotion)

Sub-skill of [Skill 07 — Contract Drafting](SKILL.md). Read the master workflow + [TEMPLATE_MAP.md](TEMPLATE_MAP.md) first. Mirrors `Contracts\Addendum\`. **We treat the Addendum as the promotion document (Ayesha 2026-08-12).**

---

## When Addendum vs New Contract

Existing employee's role is changing — determine the case. **If unclear, ask:** *"Is this a promotion/change within the same team, or is the employee moving to a different team?"*

- **Same team + promotion/change → ADDENDUM (this file).** Never auto-generate a full new contract.
- **Different team / internal move → NEW CONTRACT** → [team-move-new-contract.md](team-move-new-contract.md). Never an Addendum unless Ayesha explicitly instructs.

## Template

`Contracts\Addendum\Template  - Addendum Orenda.docx` — **one plain-"Orenda" master serves all four entities** (identical copies sit in OPL\, OWT\, NIETE\; Ayesha 2026-08-12).

## Fill fields (yellow-highlighted)

**Previous contract date** · Mr./Ms. NAME · Joining date · Ending date · Designation (new role) · **Addendum A:** Job Description (inline — replaces "Mention Job Description here") + Compensation: PKR Basic Salary / PKR Medical Allowance / PKR Other Allowance / Total Earnings PKR/month inclusive of tax · **HOD Name + HOD Designation** · Acceptance: Name + CNIC NO.

## ⚠️ Two fixed lines that need a per-case ruling

1. **"The Employee's compensation remains unchanged, as confirmed in Addendum A"** — Ayesha states **changed or unchanged** for every addendum. Fill Addendum A's salary fields and adjust this line exactly per her instruction — never decide yourself.
2. **"The Employee is required to work from the office"** — hardcoded. If the employee is remote/hybrid, flag to Ayesha before finalizing.

## Required information (ask only what's missing)

Full legal name + salutation · CNIC · **previous contract date** · new designation · joining date + ending date (effect period) · compensation changed/unchanged + figures if changed · HOD name + designation · **new-role JD (ask Ayesha)** → inline in Addendum A.

## Procedure

1. Confirm same-team promotion (ask if ambiguous) → copy master to `output/contracts/<Full Name>/Addendum - <Full Name> - <New Designation>.docx`.
2. Fill ONLY yellow fields; apply the compensation ruling; clear highlighting on filled runs.
3. Run the contract validation checklist in [SKILL.md](SKILL.md) — plus the two fixed-line rulings above.
4. No new NDA for addendum-only cases unless Ayesha says otherwise.
5. Addendum/promotion email: ⏳ template pending — flag until shared.
6. Show Ayesha the completed addendum. No send without explicit approval.
